== Evidence rules

First written 2026-11-01 on `arena/68c18146-echidnabot`, based on
`ab26bd54c8bdc04da8cc48c0778a25eb774be268`. Updated 2026-11-09 with the
first kernel receipts for the receipt-boundary theory, taken at
`1443adfabb98a9e0daea562bc8dbe764442c14cc` (<<receipts>>), and with the
GraphQL authorisation obligations from #192 (<<rust-auth>>).

Tokens are the closed vocabulary of PROOF-POLICY §5: `proven`,
`proven-with-postulates`, `tested-only`, `argued`, `open`. A theory theorem
also carries a Proof Witness Grade (PWG, PROOF-POLICY §8) and, per leg, a
§2.2 correspondence state. The three are separate fields. A PWG is derived
from the receipts below, never asserted. `ConfidenceLevel::Level3` is a
runtime heuristic and is not a PWG.

Policies and pinned references are in
link:ESTATE-ROUTING-AUDIT.adoc[the routing audit]. Theory requires strict
Agda checks, with separately recorded Rocq/Lean statement correspondence and
kernel results. Rust behaviour is verified with Creusot (Pearlite contracts)
and Verus on the actual first-party code (PROOF-POLICY §1.2); a mathematical
model does not establish runtime refinement.

== Pre-existing proof material and semantic reconstruction

The old `proofs/ECHO-TYPES-AUDIT.adoc` classified the four Lean/Coq files
as prover fixtures. That remains true. Its statement that ABI scaffolding
is out of scope does NOT make that scaffolding verified.

* `proofs/coq/trivial_ok.v`: `forall (A : Prop), A -> A`.
* `proofs/lean/trivial_ok.lean`: `(A : Prop) -> A -> A`.
* New `proofs/agda/FixtureIdentity.agda`: `(A : Set) -> A -> A`.
  This is a semantic reconstruction of the constructive identity schema,
  because there was no Agda record. It is not witness transport. Rocq/Lean
  Prop and Agda Set differ; correspondence is limited to propositional
  identity and remains `open` until checked and justified explicitly.
  The Agda file checks under the strict profile (<<receipts>>, R-AGDA); the
  Rocq and Lean fixtures are prover test material (PROOF-POLICY §3), not
  recheck legs.
* `proofs/coq/admitted_stub.v` and `proofs/lean/sorry_stub.lean` are negative
  fixtures, not candidate proofs. Their escape hatches must stay intact.
  They are excluded from PWG counts, not repaired into passing fixtures.
* JSON files under `proofs/test_fixtures` are webhook/prover inputs, not proofs.

=== ABI scaffold debt (not verified)

`src/abi/{Types,Layout,Foreign}.idr` contains literal `{{PROJECT}}` module
names, unresolved holes and placeholder foreign symbols. These are templates,
not an instantiated echidnabot ABI. `HasSize`/`HasAlignment` have unrestricted
constructors and therefore do not establish actual compiler layout.
`exampleStructSize` claims 16 while its own comment describes 24 bytes.
`offsetInBounds` quantifies over arbitrary Field values without membership or
bounds premises, so it cannot be proved as written. Layout checking and
foreign pointer/lifetime obligations also remain unresolved.

Status: `open`. Do not replace holes with postulates or transcribe these
claims to Agda as if they were true. A semantic rewrite needs the actual
exported ABI, supported targets, field representations, ownership and bounds
premises; the Rust interface proof policy remains active. No new ABI symbols
or layout contracts are invented in this patch.

== Assumed boundaries (argued, not proven)

* `serde_json` at the Cargo.lock version: parsing/value representation and
  numeric/deserialisation behaviour used by ProveResult. No external proof
  was checked here. A Rust proof must name any trusted extern specification.
* Gateway trait implementers: compliance with authorised routing, extraction,
  authentication and request correlation is an obligation, not type-enforced.
* `echidna-core` at `645d7a2489c644706210e171acba6f52741ad3b8`:
  imported trust kernel behaviour. Upstream annotations alone are not a
  checked Creusot receipt for this crate and its callers.
* Any future claim of theorem truth needs the relevant prover kernel/checker
  boundary and assumptions, separately from receipt transport.

== Toolchain deviations (PROOF-POLICY §6)

`D-THEORY-TOOLS`, state `open`. The `theory` job in
`.github/workflows/proof-safety.yml` installs its checkers outside a Guix
manifest or container, because this repository has neither:

* Agda 2.8.0.2 from the official GitHub release archive, digest above;
* Lean 4.35.0 from `releases.lean-lang.org`, digest above;
* Coq from the Ubuntu 24.04 archive. Nothing pins the package version;
  `scripts/check-theory-rechecks.sh` requires 8.18.0 and fails otherwise.

Each script asserts the version it observes and fails on a mismatch. The
deviation closes when a Guix manifest or a proof-toolchain container provides
the same versions.

== Reproduction and completion criteria

`./scripts/check-agda-proofs.sh` requires Agda 2.8.0.2 (first line of
`agda --version`; the official binary prints build flags after it), ignores
stale interfaces, uses no external libraries, and runs the strict policy
flags. `./scripts/check-theory-rechecks.sh` requires Lean at the version in
`proofs/theory/lean/lean-toolchain` and Coq 8.18.0, runs each leg's negative
control first, and fails unless every axiom report is clean. Both print
source hashes, base revision and invocations. Record the observed result
here; do not edit statuses on expected success.

Still open: `cargo test --locked dispatcher::verisim_echidna`; Creusot and
Verus on any Rust obligation; Idris2 for I-GATEWAY; owner review of the
T-RECEIPT correspondence; and a Rocq 9 recheck if the estate pins one.
Completion requires backend protocol agreement, production routing and
provenance migration, implementation and interface proofs, and preserved
fixture detection.
