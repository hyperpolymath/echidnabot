= T-RECEIPT: statement correspondence (PROOF-POLICY §2.2)
:toc:

This record compares the Agda statement of T-RECEIPT with its Rocq and Lean
re-proofs, as PROOF-POLICY §2.2 requires before a recheck leg can count
toward a grade. It records the comparison only. A leg is `RECONCILED` when
this comparison exists *and* its kernel has accepted it, so each leg's state
below depends on an observed run, not on this text.

== Universe and type discipline

[cols="2,2,2,2",options="header"]
|===
|Notion |Agda |Rocq |Lean

|Claims and evidence
|`Set` (`Set₀`)
|`Set`, predicative (no `-impredicative-set`)
|`Type` (`Sort 1`)

|The warrant record
|`Warrant : Set → Set₁`
|`ReceiptWarrant : Set → Type`, a universe above `Set`
|`ReceiptWarrant : Type → Type 1`

|The soundness record
|`SoundWarrant w : Set`
|`SoundReceiptWarrant w : Type`
|`SoundReceiptWarrant w : Type`

|Empty claim
|`data Empty : Set` (no constructors)
|`Empty_set : Set` (prelude, no constructors)
|`Empty : Type` (core, no constructors)

|Unit evidence
|`record Unit : Set` (eta holds)
|`unit : Set` (inductive, no definitional eta)
|`Unit` = `PUnit.{1}` (structure eta holds)
|===

None of the three uses `Prop`. That is deliberate: a `Prop`-only
reformulation would quantify over a different class of claims, and §2.2 asks
for the same proposition, not a weaker one.

== Propositions compared

Implicit arguments are shown in braces in every column.

[cols="1,3",options="header"]
|===
|Theorem |Statement in all three provers

|`receive-with-soundness` / `receive_with_soundness` / `receiveWithSoundness`
|For every claim `{Claim}` in the base universe, every warrant `w` for it and
every soundness witness for `w`, there is an inhabitant of `Claim`.

|`empty-claim-token` / `empty_claim_token` / `emptyClaimToken`
|A warrant for the empty claim whose evidence type is the unit type and whose
evidence is its constructor. This is a definition, compared so that the next
two theorems refer to the same object.

|`no-unconditional-reflection` / `no_unconditional_reflection` /
`noUnconditionalReflection`
|A function that, for every claim in the base universe, turns any warrant for
it into an inhabitant of the claim, yields an inhabitant of the empty type.

|`no-soundness-for-empty-token` / `no_soundness_for_empty_token` /
`noSoundnessForEmptyToken`
|A soundness witness for `empty-claim-token` yields an inhabitant of the empty
type.
|===

The quantifier structure, the argument order and the result type match
term for term. The proofs are also the same terms: application of the
soundness field to the evidence field, and instantiation of the reflection
function at the empty claim.

== Residual assumptions and differences

* *Unit eta.* Rocq's `unit` has no definitional eta, while Agda's `Unit` and
  Lean's `Unit` do. No statement or proof here inspects or compares unit
  values, so the difference is not used.
* *Prelude.* Rocq loads `Init` by default, and Lean loads its core. Both
  supply only inductive definitions here (`Empty_set`, `unit`, `Empty`,
  `PUnit`). The files print their assumption sets: Rocq with
  `Print Assumptions`, Lean with `#print axioms`.
* *Equality and K.* No statement uses identity types, so `--without-K` in
  Agda has no counterpart obligation in either target.
* *No claim about Rust.* As in the Agda source, nothing here describes the
  Rust receipt parser or any network behaviour.
